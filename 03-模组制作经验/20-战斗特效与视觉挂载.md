# 战斗特效与视觉挂载

塔2 的特效通常按“出现在哪里”选择挂载通道，而不是每张卡牌只登记一个特效路径。先确定投放位置，再选择 API。

## 三类常见通道

| 通道 | 适合 | 验收重点 |
|---|---|---|
| 攻击命中特效 | 斩击、冲击、法术命中目标 | 目标中心/脚下、单目标/多目标、资源路径和结算时序 |
| 卡牌或模型驱动特效 | 自身、目标、敌方区域或全屏演出 | 触发阶段、是否与攻击特效重复、异步任务是否等待 |
| 角色或卡牌拖尾 | 卡飞、角色主题拖尾和统一色彩 | 场景路径、透明度、跟随时间和场景切换后的资源有效性 |

## 路径契约

原版特效 API 可能接受“场景内部路径”，而不是完整 res:// 路径。不要根据文件在磁盘上的路径猜参数格式；先找原版调用点和路径拼接函数。完整路径、重复扩展名或错误前缀可能让场景加载为空，并把问题表现成卡牌结算卡死。

## 异步攻击补丁

如果攻击前后钩子返回 Task，补丁必须保留原始 await 链。错误的同步 Prefix/Postfix 可能让攻击动画、伤害结算和特效播放彼此脱节。自检应同时确认：补丁形态、场景可加载数量、实际命中特效数量和攻击最终结算。

## 组织方式

为每个视觉效果保存语义名称、路径、投放位置和适用条件，卡牌逻辑不要散落大量路径字符串。多目标、随机目标、攻击者自身和全屏效果分别测试；同一张牌不要因为同时走多个通道而重复播放。

## 完成判据

静态路径存在、场景能加载、正确目标位置出现、攻击/动画/伤害时序一致、无关牌不触发、场景切换后仍可用，并且失败时日志能指出具体卡牌、通道和路径。

## 场景生成与序列化

需要新增或复制复杂 .tscn 时，优先在 Godot 环境中构造节点树，再用 PackedScene.pack() 与 ResourceSaver.save() 让引擎序列化；不要手写动画库、子节点所有权和资源引用的文本格式。

生成前递归设置子节点的 owner，生成后在无头或最小运行环境中检查节点数、动画库、自动播放、关键材质参数和依赖资源。文本能被 load() 读到，不代表运行时结构完整。

## VFX 工具的复制与生成边界

复制原版或作者场景时优先保留资源字段指纹；只有确实需要变化的字段才改。必须区分“场景可加载”和“实际渲染”：检查节点、动画库、自动播放、shader 参数驱动、挂载点和运行时画面。项目专属场景生成器不应直接当成公共模板。
