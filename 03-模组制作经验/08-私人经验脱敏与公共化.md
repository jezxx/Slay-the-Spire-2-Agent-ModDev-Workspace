# 私人经验脱敏与公共化

本文件解决一个常见误区：私人项目不是经验的禁区，但私人项目的具体内容也不能直接变成公共资料。

## 四类信息

### 1. 私人事实

只描述某个具体项目、角色、用户、素材、路径、账号、授权状态或当前进度的信息。它留在项目档案，不进入公共核心。

### 2. 可推广方法

从私人事实中提炼出的跨项目做法，例如：

- 游戏会锁定已加载的 DLL，部署前应检查进程。
- PCK 资源即使存在于工程目录，仍需检查导出过滤器、PCK 条目和运行时读取。
- 用户说“图片不对”时，需要先确认显示位置和资源层级。
- 编译成功后仍需通过真实初始化日志确认模组运行。

这类内容可以进入公共经验，但要去掉具体项目名称，并写清版本和证据。

### 3. 项目选择

某个项目为了角色设定、平衡、音效、图像或兼容性做出的选择，不应写成通用规则。可以保留“如何记录这种选择”的方法，但选择本身留在项目目录。

### 4. 尚未复核的推测

即使私人项目里暂时有效，也不能直接进入正式经验。应放入待整理经验，标记来源、版本、待验证条件和可能影响。

## 脱敏步骤

1. 找出原记录中的项目名、角色名、作者名、私人路径、素材文件名、账号、用户习惯和具体数值。
2. 将它们替换为“某个角色模组”“某类外部资源”“用户提供的项目”“目标游戏版本”等通用指代。
3. 保留真正影响结论的条件：版本、运行模式、输入、输出、错误、验证方法和限制。
4. 如果结论来自私人源码或资源，写成“私人证据提炼”，不要写成公共源码事实。
5. 用公共反编译资料、最小示例、查询工具或另一条独立证据复核。
6. 只有复核后仍然具有跨项目价值，才进入 03、04、05、06 或 08；需要其他工作区同步时再进入经验传递文档。

## 公共记录格式

    {类别: 通用经验}
    现象：
    通用结论：
    适用版本：
    证据类型：公共源码 / 运行日志 / 最小示例 / 私人证据提炼 / 多来源交叉验证
    私人信息处理：已删除项目名、路径、素材和身份信息
    限制：
    验证方法：
    建议落点：

## 不能做的事

- 不能把私人源码原样复制到公共示例。
- 不能把私人资源文件名、绝对路径或角色专属 ID 留在公共脚本里。
- 不能因为某个项目成功过，就推断所有模组都必须用相同架构。
- 不能把“私人项目验证过但公共环境尚未复核”的内容写成硬规则。
- 不能用脱敏名称掩盖仍然受授权限制的原始代码或资源。
