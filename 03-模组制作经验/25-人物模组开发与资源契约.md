# 人物模组开发与资源契约

人物模组不是“写一个 CharacterModel 子类”这么简单。选人界面、卡池、遗物池、药水池、起始牌组、资源路径、动画和本地化共同组成角色契约。

## 先确认选人入口

原版角色列表可能是硬编码数组，而不是自动从所有模型中过滤。角色类被发现、角色能按 ID 获取、角色进入选人界面是三件不同的事。创建人物前先读选人界面的调用链，确认需要框架注册、补丁还是其他正式扩展点。

## 角色模型和内容池

按当前版本逐项核对角色模型要求：性别枚举、名称/地图/对话/能量颜色、起始生命和金币、卡牌/遗物/药水池、起始牌组、起始遗物、攻击/施法延迟、特殊事件攻击表现和解锁链。

三个内容池也有自己的契约：标题、能量颜色、卡框材质、卡牌颜色和生成内容的方法可能共同影响运行时资源路径。框架池的类型列表成员还可能是 protected；覆写可见性必须按当前签名写，不能凭相似教程猜。

每个角色至少做以下断言：起始牌组可解析、池子可解析、起始遗物可解析、所有本地化键存在、选人按钮能创建、进入战斗后资源能加载。

## 资源路径和节点

角色的选人图、头像、地图标记、战斗立绘、能量盘和转场材质可能是不同资源契约。不要认为换了角色主图，其他位置会自动跟着换。路径若由模型 ID 或 slug 自动推导，先记录实际生成路径，再决定是提供影子资源、使用公开扩展点还是补丁。

动画交付遵循 23-角色动画资源交付.md；资源缺失时要有安全回退，不让角色逻辑整体失效。

## ID、本地化和改名

模型 ID 通常由模组 ID、命名空间和类型名共同生成，角色本地化键可能使用完整模型 ID 的 Entry，而不是类名。不要根据类名手写 key；从当前版本运行时注册日志和原版表确认。

创意工坊发布前可以用改名工具一次性修改清单、文件夹、PCK 根路径、工程配置、代码常量和本地化引用。发布后改 ID 通常等同于发布一个新模组，会影响订阅、存档和依赖；应在发布前定稿，并限制为安全的字母数字/下划线形式。

## 框架边界

第三方框架的正式注册、部署和版本分支优先于手写 Harmony。编译期引用存在，不代表运行期依赖已部署；运行期依赖存在，也不代表角色已经进入选人列表。环境预检、入口日志、选人界面和战斗画面要分别验证。

## 完成判据

人物模组完成至少意味着：能被发现和注册、能在选人界面显示、能开始一局、起始牌组和遗物正确、角色资源和动画真实加载、攻击/施法时序正确、地图/选人/能量/过渡资源不缺失、退出和重启后仍能复现。
