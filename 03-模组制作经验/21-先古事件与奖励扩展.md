# 先古事件与奖励扩展

先古、普通事件、对话和遗物奖励是相互连接但不相同的链路。排查“对话读了一半、按钮点不动、遗物选项消失”时，不要只查本地化。

## 生命周期边界

- 标准先古事件与普通事件的基类和注册路径可能不同；建筑师一类的特殊事件不能套用标准先古的选项逻辑。
- 事件初始化会生成初始选项。生成过程抛异常或返回空集合，玩家表象可能只是“事件提前结束”或“对话后没有按钮”。
- 调试选项通常按文本令牌匹配；令牌不匹配时，原版的 First 查找可能直接抛异常。调试入口应记录候选文本和匹配结果。
- 对话渲染链和奖励生成链是两条独立链路。对话正常不代表奖励能生成，奖励正常也不代表角色对话键完整。

## 对话本地化契约

先古对话通常由表名、先古条目、角色条目、访问段、行号、说话人和重复标记共同构成。具体键名必须从当前版本原版表和运行时代码确认，不要从一次成功的项目键名反推所有版本。

通用检查项：

- 首次访问、角色专属段和任意角色兜底段是否覆盖；
- 访问段的 VisitIndex 是否与重复段的 IsRepeating 语义一致；
- 同一段内所有行的重复后缀是否一致；
- 非最后一行是否存在继续按钮文本键；
- 特殊事件的攻击者、开始攻击和结束攻击键是否齐全；
- 缺键、空文本和非法形态是否在运行期被明确报告。

如果一个段没有任何可用对话，UI 可能表现为卡住或没有按钮，而不是清晰的“缺键”提示。因此应同时做结构对账、键覆盖对账和真实事件烟测。

## 遗物奖励与池归属

遗物被构造出来不代表它可以安全进入事件选项。很多引擎会通过遗物 ID 反查所属池；遗物没有任何池归属时，错误可能在上游标题、悬停提示或选项构造处才暴露。

新增遗物或把遗物接入先古奖励时，至少验证：

1. 模型可以按 ID 解析；
2. 读取池归属不会抛异常；
3. 稀有度、可获取方式和目标角色条件一致；
4. 选项数量大于零，文本键完整且唯一；
5. 真实点击、查看、选择和事件结束流程都能完成。

优先使用框架或引擎提供的注册 API，不要通过补丁直接向事件选项列表追加对象。若框架没有稳定入口，再记录补丁目标、重载风险和版本限制。

## 推荐自检

用运行时真正暴露的 DialogueSet、AllPossibleOptions、ModelDb 和 ResourceLoader 做断言，不要只读自己写的配置表。日志至少输出结构摘要、缺失键、无效选项、池归属和本轮版本。文本改动必须完整重打资源包，并用样例文本或指纹证明游戏读到了新值。

## 版本复核点

游戏更新后重新确认：事件基类、初始选项生成的空集合语义、对话段选择优先级、重复段规则、奖励池反查和框架注册 API。旧版本的键名和调用顺序只能作为线索。
