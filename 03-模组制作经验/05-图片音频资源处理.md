# 图片、音频和 PCK 资源处理

## 图片

先确认目标显示尺寸、透明边缘、描边层和运行时缩放方式，再处理源图。不要在已经缩小的图上反复放大、补边或重画抗锯齿边缘。

需要区分：主图、独立描边、百科白边、详情页黑边和场景中的运行时染色。它们可能来自不同资源或不同代码路径。

## 音频

先确定播放事件和触发条件，再处理音色。错误的事件路由会让声音在点击无关 UI 时播放，即使音频文件本身没有问题。

需要验证：采样率、声道、时长、峰值、电平、PCK 导入三件套和实际调用位置。为了减少机械重复，可以离线生成轻微不同的变体，但每个变体仍要进行解码和时长检查。

## PCK

资源文件存在于工程目录不代表游戏会读取。必须检查导出过滤器、导入文件、PCK 条目和运行时资源加载结果。



## 图片处理的核对表

- 先确定资源属于运行时小图、百科缩略图、百科详情图、卡面图、独立黑色描边还是白色百科描边。
- 不要把不同显示位置共用的描边层误合并；同一对象可能有主体、黑边、白边和引擎染色四条路径。
- 处理透明边缘时保留原图作为参考，先在放大预览中检查锯齿、边缘宽度和关键结构，再输出目标尺寸。
- 输出后检查 PNG 的尺寸、透明通道、边界像素和 PCK 内实际路径。

## 音频处理的核对表

- 先确认播放事件和触发条件，再处理音色。声音过大、过锐或不适配，可能是电平问题，也可能是错误的事件路由。
- 通过对比参考音频记录采样率、声道、时长、峰值、响度和瞬态；不要只凭文件名判断“轻/中/重攻击”。
- 为减少机械重复可以做轻微变体，但变体必须保持同一事件用途，逐个检查可解码、时长和峰值。
- 游戏内要测试无关按钮、牌库、地图和其他角色，确认音频没有挂在过宽的全局 UI 或通用点击事件上。

## PCK 资源闭环

资源文件在工程里存在，不代表游戏能读取。至少要完成：导入文件、export_presets 过滤器、PCK 条目、部署目录、运行时 ResourceLoader 或实际画面/声音五项中的对应检查。
