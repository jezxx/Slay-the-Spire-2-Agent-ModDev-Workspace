# 构建、打包、部署和验证

编译成功只说明代码能够生成程序集，不说明模组已经加载，也不说明资源和本地化已经生效。

## 基本闭环

1. 编译源码。
2. 生成资源包。
3. 部署 DLL、清单和 PCK。
4. 通过 Steam 启动游戏。
5. 等待真实模组初始化日志。
6. 读取正向自检和错误日志。
7. 按用户的复现步骤验证行为。

## 资源修改的特殊要求

修改图片、音频、场景或本地化后，必须重新导入和打包。只复制散装文件或只编译 DLL，不能证明资源已经进入游戏。

## 日志原则

“补丁已挂载”“命令已返回”“自检没有报错”都不是行为成功的充分证据。关键自检必须有正向结果，并且要覆盖实际调用或实际资源读取。

## 公开工作流脚本的已验证坑

- NuGet 可能因为用户临时目录中的旧 NuGetScratch 锁文件失败，错误表面上容易被误认为 SDK 或工程引用损坏。公开构建脚本隔离 TEMP、TMP、DOTNET_CLI_HOME 和 NuGet 缓存，并允许用 -TempRoot 指定 ASCII 临时目录。
- 某些受限运行环境不会提供 APPDATA、LOCALAPPDATA、ProgramFiles 等 Windows 标准变量，NuGet 会因此在 ConfigurationDefaults 阶段报“Value cannot be null (path1)”。脚本会从 USERPROFILE 和系统盘推导缺失变量；如果仍失败，先检查环境预检和 -DotnetExe 路径，不要直接修改工程引用。
- 构建脚本不能假设 bin\Release\net9.0 一定是唯一产物位置；公开脚本会在 bin\<Configuration> 下递归定位同名 DLL，并用源码时间检查旧产物。
- 只看到 dotnet build 返回成功还不够。至少要检查 DLL 存在、DLL 不早于最近源码修改，并在需要时用 -Deploy false 将编译和部署分开验证。
- 公开脚本不能写死作者的游戏盘符、私人模组名、第三方框架布局或个人工具目录。所有游戏目录和数据目录都必须由用户参数提供，默认值只能指向公开包内部的资料目录。
- 做整包自动检查时，要区分工作区元数据与原始游戏资源：manifest、workspace.json、资料清单等应严格解析；PCK 提取出的本地化文件可能只是引擎资源语法，严格 JSON 解析失败本身不代表资料损坏。


## 任务类型与验证等级

不同修改不能使用同一种“完成”口径：

| 修改类型 | 最低验证 |
|---|---|
| 纯 C# 逻辑 | 编译、DLL 新鲜度、部署、模组初始化日志、目标行为复现 |
| 本地化 | 编译、PCK 导出、PCK 条目、运行时实际文本或指纹 |
| 图片/音频 | 导入、PCK 条目、资源路径、运行时显示或播放位置 |
| 场景/UI | 导出、场景加载、运行时位置和交互行为 |
| 版本适配 | 新版本反编译/API、编译、加载和关键路径行为 |
| 创意工坊准备 | 清单、DLL/PCK 完整性、无源码暂存目录；不等于已经上传或玩家验收 |

“日志里有模组名”只能说明某个阶段看到了名字。优先寻找 Loading assembly DLL、Loading Godot PCK、Calling initializer 和 Finished mod initialization 等正向阶段证据。

## 旧产物防线

构建系统必须避免“编译通过但部署旧 DLL/PCK”：

- 从 bin\<Configuration> 下递归定位实际 DLL，不把固定 net9.0 路径当成唯一真相。
- 对比 DLL 与最近源码修改时间。
- PCK 资源修改后重新导出，不把旧 PCK 留在部署目录里冒充新结果。
- 发布暂存目录只从已经验证的 DLL/PCK 和清单构成，不从整个源码目录复制。


## 2026-10-04 实测补充

- 在受限自动化环境中，PowerShell 可能缺少 APPDATA、LOCALAPPDATA、ProgramFiles、ProgramData 等标准变量；NuGet 会在恢复阶段报 "Value cannot be null (path1)"，这不是模组引用本身损坏。先由脚本从 USERPROFILE 和系统盘补齐变量，再继续判断。
- 直接用 PowerShell 的 & dotnet 可能吞掉原生 CLI 的输出和退出码。构建、查询工具、API 导出和环境预检应使用受控进程调用，必须保留 stdout、stderr 和 exit code。
- 查询工具不是纯离线工具：引用 sts2.dll 的项目必须把当前游戏数据目录传入构建参数；不能看到 ApiProbe 能编译，就假定全部查询工具都能编译。
- C# 顶层语句的退出码要按入口形式处理：没有整数返回的程序使用 Environment.ExitCode，已经以 return 0 作为入口的程序必须保留整数返回。批量机械替换会把辅助函数的 return 2 误改坏，改完要全量编译。
