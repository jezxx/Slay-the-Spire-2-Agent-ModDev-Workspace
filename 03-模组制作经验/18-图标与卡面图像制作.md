# 图标与卡面图像制作

图像处理要先确定“这张图最终被谁读取、以多大尺寸显示、是否有独立描边”，再决定算法。截图、低分辨率反复修图和直接修改引擎压缩纹理都不能作为稳定生产流程。

## 原版资源提取

- 优先让与游戏版本匹配的 Godot/引擎解码资源，再保存为 RGBA PNG。
- 不要把截图当作无损源，也不要把压缩纹理的错误切片交给图片工具后判断资源损坏。
- 导出后记录来源版本、原始尺寸、透明范围和目标显示尺寸。

## 小图标的通用规则

- 一个明确主体、强剪影、透明背景；不要为了“丰富”加入缩小后无法辨认的细线。
- 主要色块控制在少数几组，保留一个清晰高亮焦点。
- 统一描边应在较大画布完成，再一次性缩到目标尺寸；高质量缩放比在目标尺寸逐像素补边稳定。
- 保留 RGBA，透明区 RGB 做颜色延拓，避免线性采样产生黑边/白边。
- 不要只保留最大连通块；与主体有透明缝隙的瓶盖、剑柄、火苗、碎片和装饰可能仍是必要部件。
- 验收至少使用透明底、深色底和浅色底三种背景，并在实际 UI 尺寸下观察。

## 大画布与固定卡面

先计算不透明主体的 alpha 包围盒，再决定缩放、裁切和锚点。画布中心不等于视觉中心；非对称人物或武器应同时参考 alpha 包围盒和视觉重心。

固定尺寸的竖向卡面和普通横向卡图是两条不同管线。不要把普通卡图的压缩比例、裁切规则和竖向立绘互相套用。任何“留白按头高”“主体占比”“外填充无缝”等规则，都应写成参数并在报告中记录。

## 接缝与颜色空间

当外填充和图内底色亮度相同但纹理突然中断时，问题不是简单换颜色，而是边界两侧的纹理连续性。处理时：

1. 先用连通域、局部纹理和边界梯度确认是否真的存在接缝。
2. 用图内安全区域估计外侧背景，不要在测量域外随意外推。
3. 颜色空间保持一致；线性光和 sRGB 之间只做明确、必要的转换，避免重复 gamma。
4. 所有插值、拟合和径向场在实测范围外钳位，禁止把稀疏数据外推到画布角落。
5. 输出前保存报告、前后对照和边界梯度指标，不要只凭缩略图判断。

## 交付检查

尺寸、模式、alpha 范围、主体占比、边缘像素、独立部件、源文件哈希、PCK 条目和实际显示路径都应可追溯。处理过的图片如果只在编辑器里看过、没有经过导入和运行时验收，仍不能视为完成。
