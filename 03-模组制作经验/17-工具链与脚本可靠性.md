# 工具链与脚本可靠性

工具本身也是项目的一部分。一个脚本如果依赖作者电脑的盘符、编码或进程环境，换到另一个工作区就会把环境错误伪装成模组错误。

## 路径与编码

- 脚本尽量使用 ASCII 字面量和运行时推导路径，用户素材、项目根目录和游戏目录通过参数传入。
- Windows PowerShell 5.1 读取含中文的脚本时，使用 UTF-8 BOM；跨环境工具优先避免把中文硬编码进脚本。
- 不把作者的绝对路径、账号、模组 ID、私有素材名写进公共脚本或默认配置。
- 批处理、临时目录、导出目录和部署目录分开，完成后清理生成物，但保留可复核报告。

## 进程与退出码

外部工具调用必须保留 stdout、stderr 和 exit code。不能只看 PowerShell 的命令调用是否返回，也不能把工具输出吞掉后猜测失败原因。构建工具应允许显式指定 SDK、游戏目录和临时目录。

## 查询和二进制资料

- 查询工具必须针对实际参与编译的 DLL 和当前游戏数据目录，避免误读同名旧程序集。
- 读取二进制容器时先确认格式版本、头部、偏移和压缩方式；不要把错误切片交给 ffprobe 或图片工具后据此判断资源损坏。
- 搜索文本时限定扩展名，不要对 DLL、PCK 等二进制文件做全文字符串匹配。
- 原版压缩纹理应让同版本引擎解码或使用对应解压链路；截图不是无损证据。

## Python 与图像工具

Python 工具要在启动时报告解释器、版本和依赖。图像批处理在受限机器上应限制 OpenBLAS/OMP 线程，避免并行库耗尽内存；所有诊断数字写入报告文件，不依赖管道中不稳定的 stdout。

## 修改脚本的验证

脚本改动后至少做：语法解析、最小输入烟测、错误输入烟测、路径含空格/中文的测试，以及输出文件和退出码检查。脚本能运行一次，不代表它适合批量处理。

## 工具迁移边界

从私人工作区迁移脚本时，先把输入、输出、引擎版本和外部依赖变成参数，再删除项目名称、绝对路径、默认资源名和用户专属规则。能机械确认的提取工具可以公共化；依赖某个模组的类名映射、具体卡牌数量、角色专属资源或审美参数的脚本，继续留在项目层。

当前已公共化的迁移工具包括：塔1 卡牌字段/规格/升级语句提取、占位符本地化生成、本地化空格检查、Slugify 映射对拍、T1/T2 卡牌契约断言和基于资源清单的 PCK 动态加载验证。它们只证明输入与资源链条，不替代效果语义审计和实机验收。
