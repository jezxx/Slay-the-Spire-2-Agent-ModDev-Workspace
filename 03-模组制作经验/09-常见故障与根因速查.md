# 常见故障与根因速查

这是一张跨项目故障表。先按“现象”定位，再按“根因”验证，不要看到错误文字就直接改代码。每条都应补充当前版本和实际证据。

## 构建、部署与加载

| 现象 | 优先怀疑 | 先做什么 |
|---|---|---|
| DLL 被占用、MSB3231、文件无法覆盖 | 游戏或相关进程仍持有程序集 | 关闭游戏，确认进程退出，再重新构建；不要先改权限 |
| 编译成功但游戏行为没变 | 部署的是旧 DLL 或旧 PCK | 检查 DLL/PCK 时间和哈希，确认部署目录中的文件是本次产物 |
| 日志只出现模组名，没有功能证据 | 只证明加载到某个阶段 | 为目标功能增加正向自检，再按实际操作复现 |
| 模组完全没有初始化日志 | 清单、依赖、入口或 PCK 状态错误 | 依次检查清单、程序集、依赖模组、入口方法和本轮日志时间 |
| has_pck 为假时资源路径全部失效 | 模组的 res:// 命名空间没有挂载 | 确认清单、PCK 文件和部署目录一致，再重新导出 |
| 关闭框架部署后模组静默失效 | 必需依赖没有随模组部署 | 恢复依赖部署，先看依赖加载日志，不要把问题归因于业务代码 |
| 构建错误像 SDK 或引用损坏 | 临时目录锁、缺失 Windows 环境变量或路径含中文 | 先运行环境预检，隔离 TEMP/NuGet 缓存并使用明确 SDK 路径 |

## 资源与缓存

| 现象 | 优先怀疑 | 先做什么 |
|---|---|---|
| 磁盘上有图片，游戏里没有 | 没进 PCK、过滤器漏目录、路径大小写不符或运行时路径不同 | 查 PCK 条目，再用引擎 ResourceLoader/实际画面验证 |
| 只导出 PCK 后资源仍是旧的 | 没有先完成当前版本的资源导入 | 清理失效导出缓存，重新 import，再 export-pack |
| 改了一份素材但游戏显示另一份 | 工程、部署、临时目录存在重复副本 | 全局搜索同名文件并比较部署后哈希，明确唯一权威来源 |
| 出现 invalid UID 或资源类型不对 | 旧的 Godot 导出缓存或导入缓存 | 清理限定范围内的缓存并重新导入；不要手工伪造 UID |
| 导出的场景与源 tscn 不一致 | 游戏实际读取导出的二进制场景 | 检查 exported 场景或重新导出后再验收，不能只搜源文本 |
| 图标缩小后爬边、发糊或有黑白边 | 低分辨率反复缩放、采样边界或透明区 RGB 不连续 | 在较大尺寸统一描边和清理，最后一次缩到目标尺寸，并检查 alpha 边缘 |
| 大画布人物缩小后太小或偏移 | 按画布尺寸缩放，没有按不透明主体测量 | 先取 alpha 包围盒/主要连通主体，再计算缩放和锚点 |
| 资源换了但运行时仍读旧对象 | 静态缓存持有已释放的引擎资源 | 不要长期静态保存 Godot 资源；重新加载并检查实例有效性 |

## 本地化、卡面与变量

| 现象 | 优先怀疑 | 先做什么 |
|---|---|---|
| 关键字在卡面重复出现 | 引擎会自动插入关键字文本 | 删除本地化中的重复关键字，只保留描述需要的部分 |
| 升级后的描述不变 | 使用了未被引擎读取的升级键，或没有在升级阶段修改变量/关键字 | 对照原版调用链，检查 OnUpgrade 和运行时最终文本 |
| 卡面变量显示为空或报占位符错误 | 占位符名称与 CanonicalVars 不一致 | 逐个核对变量名、类型、大小写和升级后的实例 |
| 直接打印本地化对象得到调试串 | 调用了 ToString 而非文本读取 API | 区分原始文本、格式化文本和调试表示；缺键先查 HasEntry |
| 中文缺字、界面卡死或 LocException | 键名层级、实体变体或 .next 键不完整 | 从原版 PCK 和运行时构造规则确认完整键集合 |
| 修改本地化后 SkipPack 看似成功 | 游戏仍读取旧 PCK | 本地化变化必须完整重新导入、打包并验证最终句子/指纹 |
| 富文本标签原样显示 | 使用了引擎不支持的标签 | 先从原版文本和解析器确认可用标签，不要凭名称臆造标签 |

## 机制、时序与补丁

| 现象 | 优先怀疑 | 先做什么 |
|---|---|---|
| Harmony 补丁类存在但完全不生效 | 只写了特性，没有执行 PatchAll | 在入口显式注册补丁，并用 PatchInfo/日志确认已挂载 |
| 异步动作后续逻辑提前执行 | 补丁签名丢失了原 Task 或没有等待真实完成 | 检查 async 方法的 Harmony 签名，必要时使用 ref Task 并 await |
| “出牌后”效果偶尔早一拍或漏触发 | 把开始执行当成完成，或挂错钩子 | 读原版调用链，找到结算完成后的生命周期点再挂载 |
| 卡牌短暂消失、牌堆顺序异常 | 把塔1 的 limbo/牌堆语义直接搬过来 | 用塔2 实际 Pile 状态和牌堆操作确认中间态与最终位置 |
| 随机目标或随机发牌越界、污染其他角色 | 直接使用全局集合或提前固定目标 | 复用原版资格规则和动态目标构造器，按调用时状态求值 |
| 选择、随机、指定三种从弃牌堆取牌操作实现不同 | 只按方法名判断语义 | 阅读对应 Action/Command，并做一次玩家操作复现 |
| 能力施加抛 canonical/immutable 异常 | 把规范模型直接当运行实例修改 | 按引擎要求创建可变实例，并在运行时日志中确认目标和层数 |
| 计数器不显示或显示路径不对 | Power 的 StackType、显示模型或刷新入口不匹配 | 先确认这是 Counter、Single 还是 None，再查显示刷新钩子 |

## 调试脚本与问诊

| 现象 | 优先怀疑 | 先做什么 |
|---|---|---|
| 自检全绿但功能没跑 | 自检只检查“没有失败”，没有检查“确实执行” | 输出检查次数、正向结果、实际路径和失败项，不允许空集合恒真 |
| 日志结论来自上一次运行 | 没有确认本轮日志刷新 | 启动前后比较 LastWriteTime，并只读取本轮新增内容 |
| 静态检查通过但游戏仍失败 | 静态路径存在不等于运行时能加载 | 加入真实 ResourceLoader/初始化/行为证据 |
| 批量清理误伤其他项目 | 脚本作用域过宽 | 先 dry-run，再限制根目录、扩展名和明确文件名 |
| PowerShell 脚本出现无关语法错误 | Windows PowerShell 5.1 按系统编码读取无 BOM 文件 | 含中文脚本使用 UTF-8 BOM；通用工具尽量用 ASCII 和运行时路径 |

## 使用顺序

1. 记录用户实际操作、预期结果、实际结果和首次出现时间。
2. 先确认本轮产物、部署目录、日志时间和资源包，不要先改业务逻辑。
3. 用最小复现区分加载失败、资源失败、时序失败和业务判断失败。
4. 修复后加入能证明“确实执行并得到正确结果”的自检。
5. 将稳定、跨项目、可复核的结论再写入公共经验；单次猜测留在待整理区。
