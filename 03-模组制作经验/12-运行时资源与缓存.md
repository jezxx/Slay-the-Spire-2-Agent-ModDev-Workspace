# 运行时资源、缓存与导出

资源问题要按“工程文件 → 导入缓存 → PCK 条目 → 模组挂载 → 运行时加载 → 实际显示/播放”逐层检查。磁盘上看到文件，只能证明第一层。

## PCK 的五层证据

1. 源文件存在且路径大小写、扩展名和模组命名空间正确。
2. Godot 已为当前源文件生成导入结果。
3. 导出过滤器包含目标目录和文件类型。
4. PCK 列表中存在预期条目，且条目内容是本次产物。
5. 游戏挂载后通过 ResourceLoader 或实际画面/声音读取成功。

图片、音频、场景和本地化都要走对应的完整链路。资源包格式验证通过，不等于目标游戏版本一定接受；最终仍需目标环境验收。

## 缓存和 UID

- 导出前要区分 imported 缓存和 exported 场景/资源缓存；只清理确定属于当前项目的旧导出物。
- invalid UID 通常首先指向缓存不一致或旧导出，不要手工修改 UID 伪装修复。
- 导出的二进制场景可能与源 tscn 不同，涉及节点类型、数值或纹理引用的改动要检查实际导出物。
- 同名文件可能同时出现在源码、临时目录、发布暂存和部署目录。修复前先列出所有副本，并比较内容哈希。

## 图像边缘和尺寸

- 先区分主图、黑色描边、百科白色描边、详情图和运行时染色；它们可能是不同路径，不能用一个全局描边替代。
- 大画布素材先按 alpha 包围盒或主要主体测量，再决定裁切、缩放和锚点。
- 描边应在较高分辨率完成，最后一次缩到目标尺寸；不要在 64px 等小尺寸上反复补边。
- 透明区域的 RGB 也要做合理延拓，否则线性采样会产生黑边或白边。
- 不能只保留最大连通块：瓶盖、剑柄、火苗和装饰物可能与主体有窄透明间隙。清理算法必须保留有意义的独立部件。
- 非对称 UI 图形要同时看 alpha 包围盒中心和视觉重心，不能只按画布中心对齐。

## 场景、UI 和动画资源

- 先确认运行时查找的节点类型；代码寻找 Sprite2D 时，替换成其他节点类型可能导致静默失败。
- 动画状态机中的每个动画名都要在交付物里存在；缺一个可能让整条状态机不执行，而不是只少一个动作。
- 每种视觉 cue 都应写完整基准状态，不能假设上一个 cue 会自动把颜色、透明度、缩放和偏移重置回来。
- UI 覆盖层如果不应拦截鼠标，必须设置正确的 MouseFilter；否则会出现悬停、点击或拖拽被遮挡。
- 场景切换后重新使用 Godot 资源时，检查实例是否仍有效，避免静态缓存持有已释放对象。

## 运行时断言

资源自检应尽量使用与游戏相同的加载方式。File.Exists 只说明文件系统有文件，不能替代资源加载；PCK 内部路径也不能用源码绝对路径断言。报告中至少保留：路径、资源类型、加载结果、来源包/副本、版本和失败原因。
