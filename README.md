# Slay the Spire 2 Mod Development Agent Workspace

面向 Agent 的《杀戮尖塔 2》（Slay the Spire 2 / STS2）模组制作工作区。

## 下载后，直接交给 Agent 开始制作

这是一个下载后就可以直接交给 Agent 使用的《杀戮尖塔 2》模组制作工作区。它不是需要用户先自行搭建的空模板，而是已经准备好规则、教程、反编译资料、工具、模板和项目管理方式的完整工作环境。

把整个仓库下载到任意位置，把文件夹路径交给你的 Agent，并告诉它你想制作什么。Agent 可以先读取工作区规则，再直接开始创建、修改和验证模组内容。

首次使用时，可以直接发送：

> 这是我的 Slay the Spire 2 mod development 工作区，路径是：`这里填写路径`。请先读取根目录的 `AGENTS.md`、`README-先看这里.md`、`workspace.json` 和 `00-开始这里/`，再协助我完成任务。

如果你还没有明确想做什么，也可以让 Agent 根据工作区已有的资料，提出几个适合新手、能够真正完成的模组方向。更完整的中文说明请阅读 [README-先看这里.md](README-先看这里.md)。

## 这个工作区已经准备了什么

它不是只有几个教程链接，而是一套已经整理好的 Agent 工作环境。拿到文件夹后，Agent 可以直接利用其中的规则、资料和工具开始工作，不需要每个用户重新下载教程、寻找反编译文件，或者重新摸索项目应该如何组织。

### 已经沉淀的资料

- 已整理官方与社区模组教程，覆盖基础环境、卡牌、遗物、能力、药水、附魔、人物、事件、怪物、Patch、动画、特效和音频等方向。
- 已保存当前资料基线对应的《杀戮尖塔 2》反编译源码、API 索引和来源记录，方便 Agent 从游戏实际实现出发查找答案。
- 已按资料、经验、工具、模板、示例和用户项目划分目录，减少不同模组之间互相污染。

### 已经准备的 Agent 工作流程

- 有根目录规则和首次启动流程，告诉 Agent 进入工作区后先读什么、如何判断当前任务属于哪个项目。
- 有用户档案、项目档案、任务记录、决策记录、测试记录和交接规范，能够持续记录用户习惯和项目状态。
- 有故障问诊流程：用户只说“有 Bug”时，Agent 会继续确认操作顺序、所在界面、预期结果、实际结果、复现条件、日志和截图，而不是直接盲目改代码。
- 有版本冲突处理规则：发现游戏版本和资料基线不一致时，保留旧资料，重新反编译并记录适配影响。

### 已经准备的制作基础

- 有新建模组、卡牌、遗物、药水、Power、事件、人物和资源处理等模板入口。
- 有 C# 模组工作流、查询工具源码、构建部署脚本，以及图片、音频、PCK 和常用资源处理工具说明。
- 有最小示例和公共经验文档，帮助 Agent 从一个可解释的小例子开始扩展，而不是从空项目猜测。

### 已经考虑的真实使用方式

- 09-用户项目区/ 可以同时保存多个互不相关的模组，每个模组拥有自己的项目资料和任务记录。
- 10-用户手动添加素材区/ 是用户指定图片、音频、视频和参考文件的暂存区，Agent 会先确认用途，再决定是否接入项目。
- 有待整理经验区和跨工作区经验传递文档，能够把已经验证、值得推广的方法交给其他工作区，而不会把私人项目细节混进公共资料。

这些内容的目标不是替用户决定要做什么，而是让 Agent 在用户还没有明确想法、描述不够准确，或者遇到陌生问题时，仍然有具体的资料和方法可以继续推进。

这个仓库把制作模组时经常需要重复准备的内容集中在一起，包括：

- Mod development 教程和资料来源
- 按版本整理的反编译源码与 API 索引
- C#、Godot、PCK 和资源处理相关工具
- 卡牌、遗物、药水、Power、事件和人物等模板
- Agent 工作流、故障问诊、项目记录和经验文档
- 用于多个本地工作区之间交换公共经验的文档

## 目录入口

- `00-开始这里/`：首次使用、版本判断和故障问诊
- `01-官方与社区教程/`：本地教程资料
- `02-游戏反编译资料/`：版本化源码和 API 资料
- `03-模组制作经验/`：已验证的通用经验
- `04-工具/`、`05-模板/`、`06-示例项目/`：工具、模板和通用示例
- `09-用户项目区/`：用户自己的多个模组项目
- `10-用户手动添加素材区/`：交给 Agent 的图片、音频和参考文件暂存区

## 项目边界

这是一个公共制作工作区，不是某个具体角色模组的源码仓库。用户自己的模组应放在 `09-用户项目区/` 的独立目录中；临时素材应先放在 `10-用户手动添加素材区/`。公共经验通过审核后再进入公共目录。

反馈、Bug 和可推广的制作经验，请参阅 [贡献说明](CONTRIBUTING.md)。
