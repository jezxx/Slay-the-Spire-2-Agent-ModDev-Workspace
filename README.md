# Slay the Spire 2 Mod Development Agent Workspace

面向 Agent 的《杀戮尖塔 2》（Slay the Spire 2 / STS2）模组制作工作区。

> [!IMPORTANT]
> **下载后，直接把整个文件夹交给 Agent，就可以开始模组制作。**
>
> 这里已经准备了规则、教程、反编译资料、工具、模板和项目管理方式。用户不需要先自己搭建目录，也不需要先学会 GitHub。

## 快速开始

1. 下载或克隆整个仓库，不要只拿其中一个目录。
2. 把文件夹放到电脑上的任意位置。
3. 把工作区路径交给 Agent，并告诉它你想制作什么。
4. Agent 会先读取工作区规则，判断任务需要哪些资料和工具，再开始建立或修改模组。

可以直接发送：

> 这是我的 Slay the Spire 2 mod development 工作区，路径是：这里填写路径。请先读取根目录的 AGENTS.md、README-先看这里.md、workspace.json 和 00-开始这里/，再协助我完成任务。

如果还没有想法，可以发送：

> 我还不知道想做什么。请根据这个工作区已有的资料，提出几个适合新手、可以真正完成的模组方向，并说明每个方向需要什么。

## 这个工作区已经准备了什么


> **发布边界：** 本仓库是 Agent 制作工作区，不是游戏模组 Workshop workspace。要发布实际模组，请用工作流脚本生成 content/、workshop.json 和预览图组成的独立暂存目录；详见 [创意工坊发布格式说明](00-开始这里/创意工坊发布格式说明.md)。

> **当前边界：** 这是一个可以直接交给 Agent 开始工作的公共基础包，已经包含教程、版本化反编译资料、查询工具、原生模组模板和工作规则；但它不是某个个人模组工作区的完整复制品，也不是所有制作方向都已经完成的一键流水线。需要 Godot/PCK、第三方框架、Java 反编译或创意工坊发布时，仍需按任务安装工具并遵循对应资料。

| 内容 | 作用 |
| --- | --- |
| 教程和来源记录 | 从基础环境到卡牌、遗物、药水、Power、人物、UI、动画、特效和音频的制作入口 |
| 版本化反编译资料 | 从游戏实际程序集和 API 出发查找实现方式，并记录版本差异 |
| Agent 工作规则 | 规定先读什么、如何识别用户描述、如何分项目、如何验证和记录 |
| 故障问诊流程 | 用户只说“有 Bug”时，继续收集操作顺序、预期结果、实际结果和证据 |
| 工具与模板 | 新建模组、原生 C# 构建、资源处理和常见对象的起始模板 |
| 多项目目录 | 在同一个工作区中分别保存多个互不相关的模组 |
| 经验交换文档 | 在不同工作区之间传递经过验证、值得推广的公共经验 |

## 你可以让 Agent 做什么

- 从一个模糊想法开始，帮你选出可完成的模组方向。
- 创建卡牌、遗物、药水、Power、事件、人物、UI 和资源。
- 阅读反编译资料，确认原版行为，再决定复用、Patch 或重新实现。
- 处理图片、音频、PCK 和其他模组资源。
- 编译、部署、测试，并在出错时区分代码问题、资源问题、版本问题和环境问题。
- 记录用户习惯、项目决策、踩坑和已经验证的方法，减少下次重复摸索。

## 使用前提

“直接交给 Agent”表示可以直接开始读取、规划和建立模组项目，不表示每台电脑都已经安装了所有开发工具。

- **原生 C# 模组：**通常需要 .NET 9 SDK、已安装的游戏和游戏数据程序集。
- **图片批处理：**使用相关脚本时需要 Python 3、numpy 和 Pillow。
- **Godot、PCK、场景和部分可视资源：**按任务需要 Godot .NET/Mono 版本及对应导出组件。
- **只做规划、文档或不依赖这些工具的工作：**不需要先安装全部工具。

Agent 会按本次任务实际需要的路线进行环境检测。缺少条件时，它应该明确告诉你缺少什么、为什么需要，以及下一步怎么补齐，而不是把环境错误当成代码 Bug。

详细说明和检测命令见 [环境检测与前置条件](00-开始这里/环境检测与前置条件.md)。

完整的编译、PCK、重启验证、API 导出和查询工具入口见 [公共工作流](04-工具/工作流/README.md)。

## 两个需要记住的文件夹

**09-用户项目区/**

每个模组单独建立目录，拥有自己的项目档案、任务记录、决策记录和测试记录。不同模组之间不会自动共享源码、素材、数值或审美决定。

**10-用户手动添加素材区/**

如果你有指定的图片、音频、视频或其他文件要交给 Agent，可以先放到这里。Agent 会先确认它属于哪个项目、用于哪里，以及是正式素材还是试听/预览素材。

这个目录下的 agent生成/ 子目录用于存放 Agent 生成的临时预览图、试听音频和其他给用户确认的文件。你可以先在这里查看、试听和决定效果；确认后，Agent 再把正式版本放进对应项目。

## 项目边界

这是公共制作工作区，不是某一个角色模组的源码仓库。用户自己的模组应放在 09-用户项目区/ 的独立目录中，临时素材应先放在 10-用户手动添加素材区/。公共经验通过验证和筛选后，才进入公共目录或经验传递文档。

当前发行包属于内容测试版，资料基线、工具范围和再分发状态见 workspace.json。

公共包的覆盖等级和“何时可以称为完整公共工作区”的标准见 [公共内容覆盖清单](00-开始这里/公共内容覆盖清单.md)。
