# Agent 启动流程

## 用户已经有明确需求

1. 读取根目录 AGENTS.md。
2. 读取 workspace.json。
3. 读取经验传递文档.md，判断是否有待整合的公共变化；没有就继续，不要把它当作完整知识库。
4. 读取本地用户档案和目标项目的 PROJECT.md。
5. 根据需求分类：代码、卡牌、遗物、药水、Power、附魔、角色、UI、美术、音频、构建或故障。
6. 通过索引定位相关教程、经验和 API，不通读所有原始资料。
7. 修改前确认用户现有项目状态和已有改动。
8. 完成修改、验证和任务记录，并判断是否需要写入待整理经验或公共经验传递队列。

## 用户没有明确需求

Agent 不应只回答“请描述得更详细”。应先根据用户感兴趣的主题提供几个实际可做的方向，并说明玩家会看到什么、实现难度、所需资料、是否适合第一次制作、最小可行版本和后续扩展方式。

用户选定方向后，再在 09-用户项目区/ 建立独立项目目录、PROJECT.md 和任务记录。

## 用户第一次使用

不要一开始要求用户填写长问卷。先使用默认用户习惯参考模板，只有遇到真实歧义时才询问一个最能区分调查方向的问题。用户明确确认的称呼和工作习惯再写入本地档案，不能因为一次猜测就改公共规则。

## 一个工作区包含多个模组时

每个模组都必须在 09-用户项目区/ 中独立保存。处理任务时先确认目标项目，不要在项目之间复制源码、资源、数值或审美决定。项目之间只有经过验证、脱敏并确认具有普遍价值的方法，才可以进入公共经验层。

## 经验整理和交换

遇到新方法时，先写入当前项目记录或待整理经验/。经过版本和行为验证后，再按内容性质放入 03-模组制作经验、04-工具、05-模板、06-示例项目或 08-Agent工作流。

只有值得其他无关工作区同步的公共变化才写入根目录经验传递文档.md。交换时由接收方对照本地文件落实和验证；处理完成后清除对应记录，未解决的冲突保留。

## 版本不一致

读取 workspace.json 和环境检测结果。如果当前游戏版本不同于资料基线，保留旧资料并建立新的版本目录，记录重新反编译、差异分析和验证结果，不直接覆盖原有证据。
