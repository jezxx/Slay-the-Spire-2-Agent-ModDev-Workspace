# Agent 启动流程

## 环境检测

环境检测在真正需要编译、处理资源、导出或发布时才运行，不是每次任务的启动步骤。先根据任务路线判断前置条件：

1. 原生 C# 编译：检查 .NET 9 SDK、游戏目录和 data_sts2_windows_x86_64 中的编译引用。
2. 图片脚本：需要时检查 Python 3、numpy 和 Pillow。
3. Godot/PCK/场景：需要时检查 Godot .NET/Mono 和对应导出组件。
4. 只做规划、文档或不依赖这些工具的工作：缺少可选工具不应阻塞任务。

需要检测时使用 `04-工具/工作流/check-environment.ps1`。只改文案、数值、配置、路径或 Markdown 时不运行全环境检查。检测失败时报告“缺少前置条件”，不要把它当成代码 Bug，不要静默修改目标框架，也不要自动安装未知软件。

## 用户已经有明确需求

1. 读取根目录 `AGENTS.md`。
2. 读取 `workspace.json`。
3. 读取 `经验传递文档.md`，判断是否有待整合的公共变化；没有就继续，不要把它当作完整知识库。
4. 确认目标模组，读取它的 `PROJECT.md`；目标不明确时再问。
5. 检查目标仓库的 Git 状态和任务相关 diff，保护已有修改。
6. 按根规则判定快路径、标准路径或严格路径。
7. 只通过索引定位本任务直接相关的教程、经验和 API，不通读全部资料；正常情况下不向用户汇报检索过程。
8. 缺少会改变实现的关键参数时先问，不得脑补。
9. 完成修改和匹配风险的验证；按任务档位决定是否写项目记录或公共经验。

环境文档和工作流模板按需读取，不再作为每个任务的固定启动链。

## 用户没有明确需求

Agent 不应只回答“请描述得更详细”。应先根据用户感兴趣的主题提供几个实际可做的方向，并说明玩家会看到什么、实现难度、所需资料、是否适合第一次制作、最小可行版本和后续扩展方式。

用户选定方向后，再在 `09-用户项目区/` 建立独立项目目录、`PROJECT.md` 和独立 Git。任务记录只在标准/严格任务确有记录价值时建立。

## 用户第一次使用

不要一开始要求用户填写长问卷。先使用默认用户习惯参考模板，只有遇到真实歧义时才询问一个最能区分调查方向的问题。用户明确确认的称呼和工作习惯再写入本地档案，不能因为一次猜测就改公共规则。

## 一个工作区包含多个模组时

每个模组都必须在 `09-用户项目区/` 中独立保存，并使用自己的 `PROJECT.md` 和 Git。处理任务时先确认目标项目。用户明确说“另一个模组做过”时，可以先按各项目档案中的“常见指代”查找可复用实现；没有这种指代时，不自动复制源码、资源、数值或审美决定。

## 经验整理和交换

遇到新方法时，先写入当前项目记录或待整理经验/。经过版本和行为验证后，再按内容性质放入 03-模组制作经验、04-工具、05-模板、06-示例项目或 08-Agent工作流。

只有值得其他无关工作区同步的公共变化才写入根目录经验传递文档.md。交换时由接收方对照本地文件落实和验证；处理完成后清除对应记录，未解决的冲突保留。

## 版本不一致

读取 workspace.json 和环境检测结果。如果当前游戏版本不同于资料基线，保留旧资料并建立新的版本目录，记录重新反编译、差异分析和验证结果，不直接覆盖原有证据。
