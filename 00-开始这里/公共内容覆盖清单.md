# 公共工作区内容覆盖清单

本文件用于判断“这个工作区能不能直接交给 Agent 开始工作”，不是要求用户逐项阅读的教程。

## 覆盖等级

- A：资料和入口齐全：Agent 可以查到来源、版本和基本做法。
- B：可以开始制作：有模板或工具，但仍需要按任务核对当前版本。
- C：可以完成闭环：有创建、构建、资源打包、部署、重启和日志验证路径。
- D：需要外部条件：工作区没有携带运行时、游戏或第三方依赖，Agent 必须先检测。
- E：不应公开复制：只能保存脱敏后的通用方法，不能复制私人项目具体内容。

## 公共包与私人项目的关系

公共包不复制某个角色模组的源码、资源、作者解包文件或项目状态。

但私人项目可以贡献公共经验。正确流程是：

1. 从私人实现中提炼方法、根因、失败方案或工具设计。
2. 删除角色名、项目名、私人路径、账号、素材和不可公开代码。
3. 把具体对象改为通用指代，明确哪些结论只在某版本验证。
4. 用最小公开示例或当前公共资料复核。
5. 通过门槛后写入 03-模组制作经验/、04-工具/、05-模板/、06-示例项目/或 08-Agent工作流/。
6. 值得其他工作区同步的变化再进入根目录经验传递文档.md。

## 完成标准

只有在以下条件都满足后，才能把公共包称为“当前版本可直接交给 Agent 的完整公共工作区”：

- 每个声称支持的制作方向都有资料入口、版本边界和下一步路径。
- 原生代码至少能创建、编译、部署并通过真实日志验证。
- 资源项目能导出 PCK，且有 PCK 条目和运行时读取检查。
- API 和反编译资料可以按当前游戏版本重新生成，旧版本不会被覆盖。
- 缺少 .NET、Godot、Python、Java、CFR、ILSpy 或第三方框架时，Agent 能明确指出前置条件。
- 私人资料只贡献经过脱敏和复核的通用结论。
- README、版本说明、资料清单和工作区规则对实际内容没有夸大描述。
- 以 00-开始这里/公共工作区完成审计.md 记录本地烟测、外部依赖和仍未验证的边界。


## 经验覆盖状态

本轮已将私人工作区中可跨项目复用的中层经验抽取到 03-模组制作经验/，包括故障根因速查、机制时序、本地化变量、资源缓存、自检证据、依赖注册、塔1移植语义、媒体验收和脚本可靠性。私人项目的具体实现、素材、角色设定、路径和当前状态仍不在公共包内。
