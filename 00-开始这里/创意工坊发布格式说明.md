# 创意工坊发布格式说明

更新时间：2026-10-04

## 结论

本公共工作区不是一个可直接作为游戏模组上传的 Workshop workspace，也不应把整个工作区直接放进创意工坊。

它是 Agent 的制作资料包，里面包含教程、反编译资料、经验文档、工具、模板和用户工作区规则。创意工坊发布物则应当是某一个已经编译完成的实际模组。

## 官方上传器需要的结构

官方上传器当前使用的是独立的 Workshop workspace。典型结构如下：

~~~text
MyModWorkshopWorkspace/
  content/
    MyMod.json
    MyMod.dll       # 如果模组有原生代码
    MyMod.pck       # 如果模组有 Godot 资源
  workshop.json
  image.png
  mod_id.txt       # 更新已有项目时使用
~~~

其中：

- content/ 放实际模组文件，不放源码、教程、反编译资料或整个工作区。
- workshop.json 保存创意工坊元数据。
- image.png 是预览图，文件必须小于 1 MB。
- mod_id.txt 用于更新已有 Workshop 项目时识别项目 ID。
- 模组本体通常是匹配的 ModId.json，以及按清单决定是否存在的 ModId.dll、ModId.pck。

## 当前工作区的关系

根目录的 workspace.json 是本公共工作区的资料清单，不是官方上传器使用的 workshop.json。

仓库根目录目前没有 content/、workshop.json 和 image.png，所以不能直接交给官方上传器作为一个可用模组发布。

prepare-workshop-package.ps1 现在负责把某个具体模组的 DLL、PCK 和 JSON 放入 content/，并建立官方 Workshop workspace 的暂存结构。它不会替用户填写创意工坊文案，也不会上传账号凭据。

## 旧教程提醒

工作区内附带的社区教程副本中，Workshop Upload 页面仍可能写成 Content、workspace.json 和 image.jpg。那是教程版本中的旧写法。执行上传前，应以官方上传器当前 README 和上传器实际生成的模板为准。

## 发布边界

- 公共工作区：适合 GitHub、压缩包或其他文件分发方式。
- 实际模组：适合 Steam 创意工坊，上传编译后的 content/ 内容。
- 不建议把公共工作区伪装成游戏模组。即使文件被上传，游戏也不会因此把教程、工具和反编译资料当成模组内容加载。

## 工作区资料型 Workshop 包

如果希望让不会使用 GitHub 的用户从创意工坊取得工作区，可以发布一个“资料/教程资源包”外壳：

- 根目录使用官方上传器需要的 workshop.json 和 image.png。
- content/ 中放一个仅用于说明的模组清单，以及 workspace.zip。
- workspace.zip 保存完整公共工作区，排除 .git、构建缓存、bin 和 obj。
- 清单中的 has_pck 与 has_dll 都应为 false，并把 affects_gameplay 设为 false。
- Workshop 文案必须明确它不是可加载的玩法模组；用户需要解压压缩包后，把整个文件夹交给 Agent。

这种包的“可发布”指能作为创意工坊资料项目上传，不等于游戏会把它当成有卡牌、遗物或角色内容的模组加载。若以后要做成游戏内可识别的无操作入口，需要在装有 Godot 或 .NET SDK 的环境中额外生成并验证最小 PCK/DLL，不能用空文件冒充。

可重复生成入口：

~~~powershell
powershell -ExecutionPolicy Bypass -File .\04-工具\工作流\build-agent-workspace-workshop-package.ps1 -WorkspaceDir . -OutputDir ..\StS2-Agent-ModDev-Workspace-Workshop
~~~


本次生成的工作区资料包默认使用 `visibility: friends_only`，适合先发给好友测试；正式公开前应在 Steam 创意工坊页面确认说明、下载内容和封面均正确。
