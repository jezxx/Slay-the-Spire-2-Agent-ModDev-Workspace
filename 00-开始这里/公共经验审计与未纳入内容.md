# 公共经验审计与未纳入内容

更新时间：2026-10-04

本文件回答一个具体问题：私人工作区里已经积累的内容，哪些被提炼进公共经验区，哪些没有，以及未纳入是否是遗漏。

## 已提炼到公共经验区

已经从私人经验索引、故障速查、环境工作流、API 规则、资源转换、变量占位符、运行时资源、动画交付和音频处理记录中抽取并重写了以下公共主题：

- 构建、部署、旧产物、PCK、缓存和运行时资源加载。
- 机制/API 取证、异步时序、牌堆、随机性、目标合法性、注册和可变模型。
- 本地化键、关键字自动插入、升级、DynamicVar、文本断言和完整打包。
- 图片尺寸、alpha 包围盒、描边、透明边缘、固定卡面、图标和接缝验收。
- 音频事件路由、参考音频对比、响度/瞬态、变体、导入链和误播排查。
- 动画状态机、视觉 cue、UI 覆盖层、预览/提交状态和战斗特效挂载。
- 正向自检、本轮日志、四层证据、指纹、计数、dry-run 和最小回归验证。
- 塔1 到塔2 的语义映射、工具链编码、外部进程、二进制资料和 Python 图像工具可靠性。
- 先古事件与奖励生命周期、队列/计数状态投影、角色动画交付、人物模组资源契约和附魔/卡池多重资格门槛。
- 引擎路径变换、影子资源、配置集合对账、加载到渲染的证据推进和干净导入。
- 随机、回放与联机一致性，复杂场景的引擎序列化和运行时结构验收。

对应文档位于 03-模组制作经验/09 至 25，并已登记到资料清单。第二轮检查又补充了随机与回放一致性、复杂场景引擎序列化、先古事件与奖励、队列状态投影、角色动画资源契约、扩展资格多重门槛和人物模组资源契约。

## 有意没有纳入公共经验区

以下内容不是忘记复制，而是明确留在项目层或证据层：

### 当前私人项目状态

具体模组当前完成度、卡牌/遗物/能力数量、待办列表、用户拍板记录、当前 bug 清单和当前部署状态。这些信息只对原项目有意义，放入公共区会误导其他工作区。

### 角色和作品专属内容

角色语气、人设、称呼习惯、专属机制、具体数值、牌名、遗物名、音效选型、图片构图和动画表。这些可以作为其他项目建立用户档案的参考方法，但具体内容不跨项目复制。

### 私人源码、资源和绝对路径

完整模组源码、作者模组反编译产物、未授权资源、原始音频/图片、私人路径、账号、工具缓存和临时诊断产物不进入公共包。即使把名字改成泛称，仍然不能把受限原始内容当作公共内容。

### 只对某个实现成立的架构

某个具体模组的特效登记表、角色动画工厂、卡牌动态文案规则、专属自检数量和局部补丁没有直接复制。公共区只保留可以跨项目复用的抽象原则；要使用具体架构，必须在新项目中重新验证。

### 尚未达到证据门槛的结论

只在一次运行中碰巧有效、只依赖私人环境、版本日期超出当前基线、没有最小复现或与其他证据冲突的内容，保留在待整理区或私人记录中，不写成公共硬规则。

## 仍可继续提炼的候选

如果以后要继续扩充公共经验，优先从以下方向抽取，但每条都要重新检查版本和授权：

- 更完整的角色动画交付检查表，但不能带入具体角色资源。
- 更通用的事件、商店、设置和状态栏扩展模式，但要先用公开最小示例复核。
- 更完整的 UI 悬停布局、状态投影和多入口去重方法，但要删除具体模组状态名。
- 适配新版本后出现的新 API 语义差异，以及旧结论被推翻时的迁移记录。
- 更完整的多人事件同步、存档序列化和角色特有扩展点，当前只保留公共判断原则，未复制具体实现。
- 私人项目根规则中的证据优先级、移植先找源码、配置与真实对象对拍、过程表达和完成汇报方法，已提炼到公共 AGENTS.md；项目路径、用户称呼和具体模组规则未复制。

这些候选不是当前缺陷，也不应在没有新证据时强行写入。

## 结论

本次从头到尾复核后，没有发现还应直接写入公共经验区、但当前遗漏的高置信度项目通用规则。剩余候选属于需要公开最小示例或工具迁移后再处理的内容。

当前公共经验区不再只有基础入门内容，已经覆盖“常见任务如何做”和“失败后如何定因”的中层方法。公共区仍然不会、也不应该等同于私人工作区；它缺少的具体项目内容，是边界设计的一部分，不是整合失败。


## 工具层的另外发现

本轮重点是把“经验”转入公共文档，不把私人脚本直接混进公共工具目录。私人工具中仍有几类值得下一轮单独处理的候选：

- 可参数化后跨项目复用的塔1卡牌字段提取、卡牌契约对拍和本地化生成工具。
- 可移植的 PowerShell BOM 修复、PCK 服务级验证和固定尺寸卡面图像工具。
- 只依赖当前项目素材、私有路径、特定角色或用户审美的药水、头像、连续技、美术和攻击音频脚本，继续留在项目层。
- 本轮已把可参数化的塔1 卡牌提取、升级/规格提取、本地化生成与空格检查、Slugify 对拍、PCK 资源清单验证迁入 04-工具/通用脚本；事件/药水/卡池专属断言和项目资源转换脚本仍因映射规则绑定具体模组而暂不迁移。卡牌契约断言已改成显式输入的 T1/T2 通用版本。

这些工具不能直接复制：它们需要先去除项目字段、改成用户参数、补最小示例和错误输入测试，再进入 04-工具/。因此它们目前属于“工具迁移候选”，不是公共经验文档缺口。
