# 故障问诊与证据收集

这份文档用于处理“有 bug”“不对”“卡住了”“没有反应”这类信息不足的反馈。目标不是让新手学会技术术语，而是让 Agent 用最少的问题得到能定位问题的证据。

## 第一轮先确认现象

一次只问最关键的问题，优先使用下面的自然语言：

1. 你当时在游戏的哪个界面？战斗、地图、选人、百科、卡组、设置，还是模组加载时？
2. 你具体做了什么操作？请从点击哪个按钮、拖哪张牌或进入哪个页面开始按顺序说。
3. 你原本希望看到什么？实际看到了什么？
4. 是完全没有反应、卡住不动、游戏闪退、出现红字、画面不对，还是声音不对？
5. 这个问题每次都能重复，还是偶尔发生？

不要把这些问题一次全部丢给用户。先问最可能区分根因的问题，再根据回答继续追问。

## 用户不熟悉术语时

不要问“这是哪个 Power 的 ModelId”或“调用的是哪个 Hook”。改问用户能直接观察到的内容：

- 这个图标是在人物血条旁边、右上角遗物栏、卡牌上，还是百科页面？
- 是点击卡牌前、拖动卡牌时、卡牌打出后，还是回合结束后发生？
- 是整张牌不见了，还是牌还在但位置错了？
- 是完全没有声音，还是错误的声音被播放了？

## 需要用户提供的材料

根据问题类型选择材料，不要求用户一次提交全部内容：

- 画面问题：截图，最好包含完整界面和发生问题的对象。
- 卡牌或 UI 问题：说明操作前后状态，必要时提供录屏。
- 闪退或红字：错误文字、崩溃时间和日志末尾内容。
- 模组没加载：游戏版本、模组文件夹位置、模组清单和启动日志。
- 资源没生效：资源文件名、显示位置、修改后是否重新打包。
- 声音问题：什么操作播放了什么声音，是否每次都播放，是否只是音量或音色不对。

## 发现用户和 Agent 可能理解的不是同一个对象

如果源码和日志都找不到与描述相符的现象，先暂停修复，重新确认对象和显示位置。例如：

```text
你说的“遗物图”是指战斗中右上角的小图，还是百科列表里的缩略图？
你说的“状态”是人物状态栏里的 Power，还是卡牌描述中的状态关键词？
```

不要因为搜索不到就随意替换相近文件。

## Agent 的调查顺序

1. 把用户描述转成“操作 → 预期 → 实际”的最小复现步骤。
2. 确认对象、显示位置、版本和是否可重复。
3. 搜索现有项目文档和已知坑。
4. 搜索真实调用点、资源路径和当前版本程序集。
5. 用日志、自检、资源包或最小测试确认根因。
6. 只修改能解释该现象的最小范围。
7. 验证同一复现步骤，并检查相关的基础态、升级态、预览态和运行态。
8. 记录现象、根因、修法、证据和仍未确认的部分。

## 不允许的处理方式

- 信息不足时直接重写一大片代码。
- 只因为用户说“没有反应”就判定为事件、Power 或资源加载问题。
- 只看编译成功，不验证游戏内行为。
- 把“补丁已挂载”当成“补丁已执行”。
- 用 Agent 的术语替换用户原话后，就不再确认双方指的是同一个对象。
