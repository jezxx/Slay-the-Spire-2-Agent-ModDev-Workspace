# 项目档案规则

每个用户模组都应在 `09-用户项目区/` 下拥有独立目录、独立 `PROJECT.md` 和独立 Git，不要让多个模组共用一份当前状态或提交历史。

项目档案至少记录：

- 模组名称、作者和模组 ID。
- 目标游戏版本和模组 API 基线。
- 项目类型和当前阶段。
- 已完成内容、正在处理内容和已知问题。
- 项目专用术语、数值和不可随意改变的设计。
- 用户常用的口语指代，以及其它项目可以来这里查找的现成做法。
- 证据、工具、素材和数据入口。
- 最近一次编译、部署和实机验证时间。
- 任务记录、决策记录和测试记录的位置。

项目档案属于本地项目层。公开包只提供模板，不包含任何私人模组的实际档案。即使多个项目属于同一个用户，也要分别保存当前状态和决策。

## 项目经验的提升路径

快路径不写任务记录。标准路径只有产生新事实、重要状态变化或可复用方法时才记录；严格路径完整记录。无法确定能否推广时，把脱敏后的通用部分写入 `待整理经验/`。经过版本、证据和行为验证后，才整理进公共层。

只有确实值得其他工作区同步的公共变化，才另写一条简洁记录到根目录经验传递文档.md。传递文件不能代替项目档案，也不能包含完整项目源码或资源。
