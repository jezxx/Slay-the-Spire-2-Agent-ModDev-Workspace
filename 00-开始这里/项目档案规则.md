# 项目档案规则

每个用户模组都应在 09-用户项目区/ 下拥有独立目录和独立 PROJECT.md，不要让多个模组共用一份当前状态。

项目档案至少记录：

- 模组名称、作者和模组 ID。
- 目标游戏版本和模组 API 基线。
- 项目类型和当前阶段。
- 已完成内容、正在处理内容和已知问题。
- 项目专用术语、数值和不可随意改变的设计。
- 最近一次编译、部署和实机验证时间。
- 任务记录、决策记录和测试记录的位置。

项目档案属于本地项目层。公开包只提供模板，不包含任何私人模组的实际档案。即使多个项目属于同一个用户，也要分别保存当前状态和决策。

## 项目经验的提升路径

项目中遇到的坑和做法先写入项目任务记录；无法确定能否推广时，复制通用部分到待整理经验/。经过版本、证据和行为验证后，才整理进 03-模组制作经验、04-工具、05-模板、06-示例项目或 08-Agent工作流。

只有确实值得其他工作区同步的公共变化，才另写一条简洁记录到根目录经验传递文档.md。传递文件不能代替项目档案，也不能包含完整项目源码或资源。
