# 环境检测与前置条件

## 先说结论

这个工作区可以在下载后直接交给 Agent 使用，但“直接使用”有两层含义：

- Agent 可以立刻读取规则、教程、反编译资料，帮用户确定方向，创建项目，编写文档和代码，并检查下一步缺什么。
- Agent 要真正编译、启动游戏、导出 PCK 或处理某些素材时，仍需要用户电脑上有对应的游戏文件和工具链。

因此，工作区不是把所有运行时都打包进来的便携开发环境。当前 `workspace.json` 中的 `contains_portable_tools` 仍为 `false`。Agent 的职责是先检测任务需要的条件，缺什么就明确报告什么，不应该为了绕过环境错误而随意改目标框架、替换 API 或编造其他修复方案。

## 按任务路线判断依赖

### 原生 C# 模组

这是工作区当前最直接的制作路线。编译前通常需要：

- Windows 和可用的 PowerShell。
- 已安装《杀戮尖塔 2》，并且能找到游戏目录。
- 游戏目录中的 `data_sts2_windows_x86_64`，其中至少能找到模板引用的 `sts2.dll`、`0Harmony.dll` 和 `GodotSharp.dll`。
- .NET 9 SDK。注意是 SDK，不只是 .NET Runtime；当前原生模板的 TargetFramework 是 `net9.0`。

Rider、Visual Studio 或 VS Code 不是硬性依赖。它们只是编辑代码更方便，C# Dev Kit 也属于可选项。

原生 C# 模板本身不要求安装 Godot 编辑器。只写卡牌逻辑、遗物逻辑、Power、Patch 或其他 DLL 逻辑时，优先走这条路线。

### 图片处理和批处理脚本

工作区的部分工具使用 Python。当前已确认的图片脚本是 `04-工具/通用脚本/make-card-375x526.py`，它需要：

- Python 3。
- Python 包 `numpy`。
- Python 包 `Pillow`，导入名是 `PIL`。

Python 不是原生 C# 模组编译的基础依赖。如果当前任务不涉及这些 Python 脚本，缺少 Python 不应阻止 Agent 继续做代码、项目规划或其他不相关工作。

### Godot、PCK 和可视资源

需要创建或修改 Godot 场景、导出 PCK、制作依赖 Godot 导出的资源、处理部分 UI、动画、特效或音频资源时，才需要按教程安装 Godot 4.5.1 的 .NET/Mono 版本及其对应导出组件。具体以 `01-官方与社区教程/SlayTheSpire2ModdingTutorials/Basics/01 - 环境配置/README.md` 的版本说明为准。

这不是所有模组都必须安装的工具。Agent 应先判断任务是否真的需要 Godot，再检查它，而不是见到“模组制作”就要求用户安装完整 Godot 环境。

### 创意工坊发布

创意工坊上传工具是另一条独立流程。工作区保存了教程和来源说明，但当前没有把官方上传器作为便携工具打包进来。需要发布时，Agent 应先检查教程要求，再确认用户是否已经准备好上传器、Steam 登录状态和发布所需文件。

## Agent 的检测顺序

Agent 进入工作区后，按照下面的顺序处理：

1. 读取根目录 `AGENTS.md`、`workspace.json` 和本文件。
2. 根据用户要做的是原生 DLL、图片批处理、Godot/PCK、发布还是仅文档规划，确定本次任务的依赖范围。
3. 运行 `04-工具/工作流/check-environment.ps1`，只检查本次任务需要的项目；不要无条件把所有可选依赖都当成硬性要求。
4. 把结果分成“已满足”“本次任务不需要”“缺少且会阻塞当前步骤”三类。
5. 如果是环境缺失，明确写出缺少的工具、检测命令、用途和用户需要安装的类型。不要把环境错误伪装成代码错误，也不要静默降低目标框架或改用未经验证的替代版本。
6. 如果当前步骤不需要缺少的工具，继续完成不受影响的工作，并把真正需要用户补齐的步骤留到编译、导出或运行前。

推荐的阻塞表达是：

> 当前被环境条件阻塞：缺少 .NET 9 SDK。已确认项目模板目标是 net9.0，因此不能用只安装 Runtime 或擅自改成其他目标框架来绕过。请先安装 .NET 9 SDK，之后重新运行环境检测。

## 用户可以自己运行的检测命令

在工作区根目录打开 PowerShell：

    .`\04-工具\工作流\check-environment.ps1

检查某个游戏目录：

    .`\04-工具\工作流\check-environment.ps1 -GameDir "C:\你的游戏目录"

检查图片脚本路线：

    .`\04-工具\工作流\check-environment.ps1 -RequirePython

检查 Godot 路线：

    .`\04-工具\工作流\check-environment.ps1 -RequireGodot -GodotExe "C:\你的Godot\Godot.exe"

也可以手动确认基础命令：

    dotnet --version
    dotnet --list-sdks
    python --version
    python -c "import numpy, PIL; print('python image dependencies: ok')"

脚本只做检测，不会自动安装、升级、删除或修改用户电脑上的软件。

## 版本条件

当前公开资料基线是《杀戮尖塔 2》0.111.0。游戏更新后，Agent 必须把当前游戏目录和运行程序集视为更高优先级证据：保留旧版资料，重新反编译或导出当前版本，比较差异并完成最小验证。缺少工具和游戏版本不一致是两种不同问题，不能混在一起处理。

## 对“下载后直接交给 Agent”的准确理解

这句话表示用户不需要先自己搭建一个模组工作区，也不需要先学会目录规划。用户可以先把文件夹交给 Agent，Agent 会从资料、项目初始化和环境检测开始工作。

它不表示所有电脑都能不安装任何东西就完成编译和运行。当前最常见的最小条件是：安装游戏并提供游戏数据目录，安装与模板匹配的 .NET 9 SDK；只有使用 Python 图片脚本或 Godot/PCK 路线时，才继续补充对应工具。
