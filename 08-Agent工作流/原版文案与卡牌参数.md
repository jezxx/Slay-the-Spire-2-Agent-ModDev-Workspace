# 原版文案与卡牌参数

## 玩家可见文案

写卡牌、Power、遗物、药水、关键字、悬停提示、附魔或事件机制文案前，先查当前版本提取件：

`02-游戏反编译资料\版本-<当前版本>\API索引\pck_extract2\localization\{zhs,eng}\`

固定顺序：

1. 先查 `card_keywords.json`，确认原版关键字和自动插入文本。
2. 在中英文全部本地化表中搜索用户给出的整句或核心片段。
3. 再按对象类型查 `cards.json`、`relics.json`、`potions.json` 等相似句式，同时搜索 `powers.json`。
4. 命中原版句子就一字不差复用，不润色；语义实现再对照当前版本源码和调用点。
5. 完全找不到或不同资料冲突时停下，向用户说明并给出可选方案。

同一效果不按卡牌、遗物、药水分家。它们可能使用同一个 Power 或命令，因此不能只查正在制作的对象类型。

## 新卡开工前参数

以下项目缺哪项就向用户问哪项，不得自行补全：

- 归属模组或角色
- 卡名
- 费用，以及升级后是否变化
- 类型：Attack / Skill / Power / Status / Curse
- 稀有度
- 目标：单体 / 全体 / 自身 / 随机 / 无目标
- 基础效果
- 升级效果
- 关键字：消耗 / 虚无 / 固有 / 保留等
- 动态数值与描述占位符
- 是否需要卡面美术
- 是否进入卡池，以及特殊解锁/生成限制

用户已经明确给出的项目不重复询问。先查项目档案和当前上下文；只有仍缺失且会改变实现的参数才提问。
