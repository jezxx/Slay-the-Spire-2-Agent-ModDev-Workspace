# 提交与回退

## 仓库边界

- 公共资料和工具使用工作区根 Git。
- `09-用户项目区\<Mod>` 中每个模组使用自己的 Git，不进入公共仓库。
- 手动素材区、缓存区、本地覆盖和待整理经验不强制建立 Git。

新建模组脚本会在 Git 可用时初始化独立仓库。现有模组第一次正式修改前也应建立仓库和基线提交；缺少 Git 身份时先请用户配置，不编造姓名或邮箱。

## 一个任务一个提交

1. 开始前运行 `git status --short --branch`，并查看任务路径的现有 diff。
2. 只修改本任务文件，不处理用户已有的其它修改。
3. 只用 `git add -- <明确路径>` 暂存。
4. 运行提交前检查和 `git diff --cached --check`。
5. 提交说明用 `对象：行为（关键数值）`，完成后报告短哈希。

快路径不需要额外任务台账。标准任务只有在重要或产生可复用事实时写项目记录；严格任务完整记录。

## 并行任务

- 不同文件可并行，暂存和提交错开。
- 同一文件默认排队，不采用“都不提交，最后一起处理”。
- 必须并行时用独立 worktree 和分支，各自提交后再合并。
- 共享状态文档和公共经验由一个整合任务单写。

## 回退

用户说“回退某某改动”时：

1. 用 `git log --grep` 和提交历史找候选。
2. 把候选说明和哈希列给用户确认。
3. 使用 `git revert <hash>` 生成可恢复的反向提交。

不要使用 `reset --hard`、`checkout --` 或 `restore` 覆盖工作区。
