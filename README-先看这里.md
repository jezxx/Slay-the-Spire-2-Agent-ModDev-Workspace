# 杀戮尖塔2模组制作 Agent 工作区

这是一个可以直接交给 Agent 使用的《杀戮尖塔2》模组制作工作区。

它面向不熟悉计算机、源码和模组制作流程的人：你只需要把整个文件夹放到电脑上，把路径告诉 Agent，再说出你想做什么。Agent 会从工作区规则、已有资料和环境检测开始，逐步帮你把想法做成可以测试的模组。

## 第一次使用

### 你需要做的事

1. 下载整个工作区。
2. 把它放到电脑上的任意位置。
3. 把文件夹路径交给 Agent。
4. 告诉 Agent 你想制作什么；如果还没有想法，也可以让它帮你挑选方向。

如果 Agent 已经打开了这个文件夹，只要直接描述任务即可。某些工具不会自动读取工作区规则时，可以补一句：

    请先读取工作区根 AGENTS.md 和目标模组 PROJECT.md，再按其中的任务分档处理：这里填写任务。

如果还没有明确想法：

    我还不知道想做什么，请根据这个工作区已有的资料，给我几个适合新手、可以真正做出来的模组方向。

### Agent 会先做什么

Agent 不会把所有资料一次性读进上下文，而是会：

1. 读取根规则，确认目标模组并检查已有修改。
2. 把任务分为快路径、标准路径或严格路径。
3. 只读取直接相关的教程、反编译资料、经验和模板。
4. 只在需要编译、资源处理、导出或发布时检查对应环境。
5. 修改并完成与风险匹配的验证；小任务不强制写计划或任务记录。

## 这个工作区包含什么

- 杀戮尖塔2模组制作教程和来源记录
- 按游戏版本保存的反编译源码与 API 索引
- 已验证的通用模组制作经验和故障处理方法
- 图片、音频、PCK 和构建相关工具源码
- 新模组、卡牌、遗物、药水、Power、事件和资源模板
- 用户档案、项目档案、任务记录和交接规范
- 帮助 Agent 从新手描述中收集有效证据的故障问诊流程
- 用于不同工作区之间交换公共经验的临时经验传递文档

## 下载后是否还需要安装东西

可以立刻把工作区交给 Agent，但编译和运行模组仍需要电脑具备对应条件：

| 任务 | 通常需要 |
| --- | --- |
| 原生 C# 模组 | .NET 9 SDK、游戏目录和游戏数据程序集 |
| 图片批处理 | Python 3、numpy、Pillow |
| Godot、PCK、场景和部分可视资源 | Godot .NET/Mono 版本及对应导出组件 |
| 只做规划、文档和项目初始化 | 不一定需要上述工具 |

Agent 应先检测本次任务真正需要的依赖。详细说明见 [环境检测与前置条件](00-开始这里/环境检测与前置条件.md)。

## 使用边界

**09-用户项目区/**

把多个模组分别放进这里。每个模组都有自己的项目档案和独立 Git；一个模组的实现细节不会自动变成另一个模组的规则。用户明确指出另一个模组已有类似实现时，Agent 会先通过项目档案的“常见指代”查找可复用内容。

**10-用户手动添加素材区/**

用户指定的图片、音频、视频和参考文件可以先放进这里。Agent 必须先确认它属于哪个项目、用于哪个界面，以及它是正式素材还是试听/预览素材，再决定是否复制到项目中。

这里的 agent生成/ 子目录用于保存 Agent 生成的临时预览图、试听音频和其他给用户确认的文件。用户可以先在这里查看或试听，确认后再接入正式项目。

**11-缓存文件存放区(定期清理/**

探针、截图、日志和中间产物统一放在这里，避免搅乱公共目录和模组源码。普通任务不需要每次清空，由用户或总管 Agent 定期整理。

## 工作时的基本边界

- 公共教程和反编译资料不等于某个具体模组的源码。
- 项目专属内容留在对应项目目录，不自动污染其他模组。
- 尚未验证的经验先放入待整理经验区。
- 只有跨项目、经过验证、值得同步的方法，才进入公共经验层或经验传递文档。
- 游戏版本变化时，保留旧资料并重新核对当前版本，不直接覆盖旧证据。
