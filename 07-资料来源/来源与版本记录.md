## 证据和结论要分开

原始代码、教程和资源是证据；项目文档中的“某 API 在当前版本应该这样用”是结论；用户或 Agent 的经验判断是经验。三者不能只用一个标题混在一起。

来源目录记录“资料从哪里来”；它不记录项目当前状态，也不承载经验传递队列。公共经验必须能回溯到版本和证据，但不要为了证明经验而把私人项目文件复制到这里。

## 版本更新

游戏版本更新后，旧资料保留在对应版本目录。新资料记录新的游戏版本、反编译日期和工具版本，并在版本对比文档中标出受影响的 API、资源路径和教程。
